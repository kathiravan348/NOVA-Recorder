## Goal
The `nova-rec` Compose stack records Kite ticks into its own database from the selection and sealed session
that NOVA pushes to `PUT /internal/sync`, with no dependency on NOVA during the day (D91 / R1).

## Build
1. One Python package `nova_rec` (3.12, uv; FastAPI, SQLAlchemy 2, Alembic, psycopg, pydantic-settings,
   websockets, cryptography; ruff, mypy strict, pytest, all pinned to NOVA's `uv.lock` versions).
2. `rev0001_initial`: `ticks` and `index_ticks` with NOVA's exact final columns, types and primary keys, as
   hypertables on `received_at` with 1-day chunks (`index_ticks.symbol` has no foreign key here);
   `sync_state` (one row: `account_id`, `api_key`, `access_token_encrypted` bytea, `expires_at`, `enabled`,
   `synced_at`); `rec_stocks` (`symbol` PK, `instrument_token` unique); `rec_indices` (`name` PK, `instrument_token`);
   `recordings` (`id`, `started_at`, `finished_at`, `status` running|completed|failed, `error`, `rows_written`).
3. Copy `ticks.py`, `crypto.py`, `recorder.py` unchanged except imports. `loop.py` = NOVA's `recorder_loop.py`
   with: selection from `rec_stocks`/`rec_indices`, session from `sync_state` (token opened with
   `NOVA_BROKER_TOKEN_KEY`, live only while `expires_at` is in the future), a `recordings` row instead of a data
   job, no Redis publish. Keep the window 08:59–15:31 IST, retries and stall watchdog exactly as NOVA.
4. `api.py` (`rec-api`): `GET /health`; with header `x-rec-internal-token` (constant-time check, else 401):
   `PUT /internal/sync` body `{accountId, apiKey, accessTokenSealed (base64) | null, expiresAt | null, enabled,
   stocks[{symbol, instrumentToken}], indices[{name, instrumentToken}]}` (≤ 3,000 instruments, else 400) replaces
   all three tables in one transaction; `GET /internal/status` → `{state: off|waiting|recording|no_login,
   syncedAt, sessionExpiresAt, stocks, indices, todayTicks, lastError}`. A sync during a recording applies at its
   next connection. Pydantic models forbid extra fields; camelCase on the wire.
5. `compose.yaml`: project `nova-rec`; services/containers `rec-postgres` (NOVA's TimescaleDB image,
   `127.0.0.1:${REC_DB_PORT:-5433}`, volume `rec-db-data`), `rec-migrate`, `rec-recorder` (restart unless-stopped),
   `rec-api` (`127.0.0.1:${REC_API_PORT:-8100}`); image `nova-rec:dev`; `rec-test-db` + `rec-check` in profile
   `tools` (tests create throwaway databases on `rec-test-db` only). Every service has a `mem_limit` (total ≤ 1 GB).
6. Guides: SETUP (first start, `.env`, check command), API (the endpoints above), DATABASE (the tables).
