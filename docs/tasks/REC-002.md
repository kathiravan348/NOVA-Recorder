## Build
1. `recorded_days` (`day` PK, IST date; `ticks`, `index_ticks`, `stocks` counts; `closed_at`; `imported_at`;
   `delete_requested_at`; `deleted_at`). An IST day = `received_at` from 00:00 to 24:00 IST.
2. **Close a day**: when the loop is outside the recording window and no recording is running, every weekday up to
   today (today only after 15:31 IST) that has ticks and no `recorded_days` row gets one with its counts. Counts
   are frozen from then on.
3. Endpoints (internal token as REC-001):
   - `GET /internal/days` → newest first `[{day, ticks, indexTicks, stocks, closedAt, importedAt, deleteRequestedAt, deletedAt}]`.
   - `GET /internal/days/{day}/stocks` → `[{symbol, ticks}]` (for NOVA-226's side-by-side check).
   - `GET /internal/days/{day}/ticks` and `/index-ticks` → streaming response of
     `COPY (SELECT <explicit column list> FROM … WHERE <IST day> ORDER BY received_at) TO STDOUT (FORMAT binary)`,
     `application/octet-stream`, header `X-Row-Count` = frozen count. 404 if the day is not closed; 410 if a delete
     was requested. Stream from the database cursor in chunks; never hold a day in memory.
   - `POST /internal/days/{day}/imported` body `{ticks, indexTicks}`: equal to the frozen counts → `imported_at = now`,
     200; else 409 with both counts; 409 if a delete was requested; repeat calls keep the first `imported_at`.
   - `POST /internal/days/{day}/delete` body `{novaHasDay: bool}`: 404 if the day is not closed; allowed only if
     `imported_at` is set or `novaHasDay` is true (NOVA already holds the day from its own recorder), else 409
     `Day not imported`. Sets `delete_requested_at = now` → 202 with the day; repeat calls keep the first time.
     Never deletes ticks inside the request.
4. **Delete**: outside the recording window, the loop deletes the ticks and index ticks of days with
   `delete_requested_at` set and `deleted_at` null (whole chunks with `drop_chunks` where the chunk holds only that
   day, else `DELETE`), then sets `deleted_at`, keeping the row. No other code path deletes ticks; no timer.
5. Column lists for COPY come from one constant per table shared with the tests; a test checks that the list
   matches the table's columns, so a schema change can't silently change the export.
