# REC-002 — Recorded days: list, export, mark imported, delete after 7 days

**Status:** in-progress · **Owner:** ChatGPT · **Branch:** task/REC-002 · **Depends on:** REC-001

## Goal
NOVA can list Recorder's finished days, stream each day's ticks, confirm the import, and Recorder deletes a

## Build
1. `recorded_days` (`day` PK, IST date; `ticks`, `index_ticks`, `stocks` counts; `closed_at`; `imported_at`;
   `delete_after`). An IST day = `received_at` from 00:00 to 24:00 IST.
2. **Close a day**: when the loop is outside the recording window and no recording is running, every weekday up to
   today (today only after 15:31 IST) that has ticks and no `recorded_days` row gets one with its counts. Counts
   are frozen from then on.
3. Endpoints (internal token as REC-001):
   - `GET /internal/days` → newest first `[{day, ticks, indexTicks, stocks, closedAt, importedAt, deleteAfter}]`.
   - `GET /internal/days/{day}/stocks` → `[{symbol, ticks}]` (for NOVA-226's side-by-side check).
   - `GET /internal/days/{day}/ticks` and `/index-ticks` → streaming response of
     `COPY (SELECT <explicit column list> FROM … WHERE <IST day> ORDER BY received_at) TO STDOUT (FORMAT binary)`,
     `application/octet-stream`, header `X-Row-Count` = frozen count. 404 if the day is not closed. Stream from
     the database cursor in chunks; never hold a day in memory.
   - `POST /internal/days/{day}/imported` body `{ticks, indexTicks}`: if they equal the frozen counts, set
     `imported_at = now`, `delete_after = now + 7 days` → 200; otherwise 409 with both counts; repeat calls keep
     the first `imported_at`.
   - `DELETE /internal/days/{day}` → only for a closed, **not imported** day whose ticks NOVA already has from its
     own recorder (side-by-side days before NOVA-226, so they do not fill the disk: ~5 GB per day); sets `imported_at` and `delete_after = now`.
4. **Delete**: outside the recording window, the loop deletes the ticks and index ticks of days with
   `delete_after < now` (whole chunks with `drop_chunks` where the chunk holds only that day, else `DELETE`), and
   keeps the `recorded_days` row. A day without `imported_at` is never deleted.
5. Column lists for COPY come from one constant per table shared with the tests; a test checks that the list
   matches the table's columns, so a schema change can't silently change the export.
